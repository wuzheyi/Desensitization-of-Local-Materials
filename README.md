# 尽调材料脱敏 · 可逆还原

把金融尽调材料里的主体信息和金额比例换成占位符，交给外部 AI 润色，再在本地把占位符换回原文。

**原始文本、实体账本、还原结果全部只存在于浏览器内存里：不上传、不落盘、不发任何网络请求。**

在线使用：<https://wuzheyi.github.io/Desensitization-of-Local-Materials/>

---

## 它解决什么问题

尽调材料不能直接丢给 AI——里面全是交易对价、客户名单、股权结构和自然人信息。但常规脱敏有个副作用：脱完就还原不回来，AI 改过的稿子再也对不上原文。

这个工具做的是「可逆脱敏」：

```
原文 ─脱敏─▶ 脱敏稿（〔机构_1〕〔金额_2〕…）─▶ 你自己的 AI 润色 ─▶ 粘回 ─▶ 按本地账本还原 ─▶ 终稿
```

工具本身不调用任何模型，只负责两件事：生成一份**可安全外发**的脱敏稿，以及把 AI 的成果**逐字还原**成能用的终稿。信息不对称只发生在 AI 那一端。

## 五步流程

页面顶部是步骤条，可以随时回到已完成的步骤重做。**标题右侧的「使用说明」**里是同一套流程的详细版（每步能做什么、能得到什么），新用户第一次打开建议先点它。

| 步骤 | 你做什么 | 你会得到 |
|---|---|---|
| 1 导入材料 | 拖入 `.docx` / `.txt` / `.md`，或直接粘贴正文；没有材料可点「载入示例」 | 纯文本正文 + 自动抽出的主体清单（默认全选） |
| 2 识别与对比 | 左右双栏逐行核对，点命中/占位符双向联动，漏脱的拖选补标记，误伤的撤销 | 一份你确认过的脱敏结果 |
| 3 导出脱敏稿 | 「复制（含提示词）」→ 粘给你自己的 AI | 一段可以放心外发的文本 |
| 4 粘回润色稿 | 把 AI 返回的全文整段粘回来 | 还原稿 + 逐条诊断 |
| 5 还原与导出 | 看诊断、通读、导出 `.txt` 或复制全文 | 占位符逐字换回真实信息的终稿 |

### 1 · 导入材料

- 文件在浏览器内解析（DOCX 用 `mammoth`，上限 40MB），不会离开这台设备。
- 导入即自动抽取主体，**候选默认全部勾选**——不需要再做一次「加入词表」的确认。
- 正文里拖选任意一段文字，下方浮出「识别为 ___ · 加入词表」，类型可改。这是补漏最快的方式。
- 清单里可以：取消勾选（不脱敏，但仍留在清单里）、点名称就地改名、下拉改类型、✕ 删除、底部手动补充。
- 日期脱敏是可选项，**默认关闭**：抹掉时间会明显降低材料可读性。

### 2 · 识别与对比

- **双向联动**：点原文任一命中处，右侧对应占位符同步高亮；点占位符，左侧原文同步高亮。同一实体在全文出现几处，就一起亮几处。
- **统计可下钻**：顶部「机构 6 / 金额 5」这类标签可点开，看这一类具体命中了哪些词、各出现几次、来自规则还是词表，点一条即定位到正文。
- **全文同步脱敏**：在左栏拖选一段文字，确认前就会告诉你「全文 N 处相同内容会一起脱敏」；标记后这些位置同时脉冲提示。
- **可撤销**：点实体卡片「撤销此项脱敏」，该内容全文都不再脱敏，受影响位置用红框加删除线标出，可一键恢复。

### 3 · 导出脱敏稿

- 提示词以文本框展示，可按需修改（可「恢复默认」）。它要求 AI 原样保留 `〔类型_序号〕` 占位符——这一条直接决定还原成功率。
- 「复制（含提示词）」把提示词与脱敏稿一起复制；也可以只复制正文，或下载 `.txt`。
- 浏览器拦截自动复制时，文本会被放进文本框并全选，按 Ctrl+C 即可。

### 4 · 粘回润色稿

- 整段粘回即可。若 AI 连占位符的括号都删了，勾上「宽松匹配」，也能识别裸写的 `机构_1`。

### 5 · 还原与导出

逐条报出三类问题，绝不静默输出一份可能还留着占位符的稿子：

- **未出现的占位符**：AI 把这一处删了，还原时无处可填
- **无法识别的占位符**：账本里没有，AI 自己编了编号
- **正文残留**：还原后正文里仍有占位符

## 识别什么

**主体与关联标识**（凡是能反查到具体主体的都算）：身份证、统一社会信用代码、手机/座机、邮箱、银行卡、注册地址、车牌、IP、股票代码（含 `.SH/.SZ/.BJ/.HK` 后缀与「代码：」上下文）、域名、完整 URL。

**金额与财务**：金额（含中文大写、括号负数、万元/亿元换算）、比例、数量。

**为什么不误伤**——误伤比漏脱更容易让人放弃工具，所以按形态分级放行：

| 形态 | 处理 |
|---|---|
| 带货币单位、`%`、`‰`、`bp`、`倍` | 必脱 |
| 带人/家/股/户等数量单位 | 数值 ≥ 100 才脱（`3 家子公司` 保留） |
| 无单位的裸数字 | 有千分位或小数点且 ≥ 1000 才脱（年份、条款号一律放过） |

**主体名称**是唯一无法靠正则兜住的部分，所以做了一层无模型的自动抽取：

| 线索 | 能抓到什么 |
|---|---|
| 机构后缀 | 以「有限公司 / 集团 / 银行 / 事务所 / 中心 / 协会」等结尾的全称，包括带括号的 `天健会计师事务所（特殊普通合伙）` |
| 「以下简称」句式 | `深圳市前海云启科技有限公司（以下简称"云启科技"）` 里的简称，绑定到同一主体 |
| 职务与称谓 | 「法定代表人：陈立平」「王振华先生」「由李明持有」这类上下文里的人名，含并列人名 |
| 项目名 | 「启元一号项目」，书名号里的非文件类名称 |

抽取是启发式的，一定有误报。默认全选的理由是「漏脱比多勾更危险」——多勾了你能一眼看见并取消，漏勾了在对比页很难发现。

进清单之后还有一层扩展：去掉行政区域和行业后缀生成别名，同一主体的不同写法都会脱。全称与简称各占一个占位符，这样还原时不会把简称替换成全称。

**自动抽取每份正文只做一次。** 你删改过清单后，不会因为一次失焦又抽一遍把改掉的内容加回来；只有主动点「重新抽取」才会重扫（仍保留你改过的条目），换了正文才会重新抽取。

## 还原是怎么做到可靠的

AI 一定会改写占位符的形态。实测中它会把 `〔机构_1〕` 写成 `【机构1】`、`(机构 1)`、`[机构_1]`，甚至断行。所以还原不能用严格的字符串替换：

- **括号种类宽松**：`〔〕 [] 【】 （） () ｛｝ 「」` 都认
- **分隔符可选**：`_`、`-`、空格、`.` 都行，没有也能匹配
- **序号归一**：`001` 与 `1` 等价
- **多占位符并列**：`〔机构_1、机构_2〕` 能拆开分别还原
- **诊断齐全**：缺失、未知、残留三类问题逐条列出

文号里的 `〔2020〕` 因为不含「类型 + 序号」结构，不会被误当成占位符。

## 隐私

- 应用是纯静态页面，**不发起任何网络请求**，不加载第三方脚本与统计。
- 原文、账本、结果都在内存里，**刷新页面即清空**（所以别在中途刷新）。
- 页面里没有任何上传、登录、云端同步入口——不是「默认不上传」，是根本没有这段代码。
- 想自行验证：打开页面后断开网络，把整个流程走一遍。

## 本地运行

**最简单：双击项目根目录的 `start.bat`。** 它会检查 Node.js、首次运行自动装依赖、固定用 **5273** 端口启动，并在服务就绪后打开浏览器。关掉那个黑色窗口就是停止服务。

命令行等价方式：

```bash
npm install
npm start         # 固定 http://127.0.0.1:5273/
npm run dev       # 同样是 5273；端口被占用会直接报错，不会悄悄换端口
npm test          # 67 个单测
npm run build     # tsc --noEmit + vite build
```

端口固定为 5273 并显式绑定 `127.0.0.1`，是为了避开本机其他占用 5173 的应用，也避免端口被悄悄改掉后你打开的是另一个地址。

## 部署到 GitHub Pages

完整步骤（需要上传哪些文件、两个硬门槛、自检清单、失败排查）见 **[docs/DEPLOY.md](docs/DEPLOY.md)**。简短版：

1. 仓库设为 **Public**，默认分支为 **main**
2. 推到 `main`，`.github/workflows/deploy.yml` 自动执行：`npm ci` → `npm test` → `npm run build` → 部署
3. Settings → Pages → Source 选 **GitHub Actions**
4. 网址：`https://<用户名>.github.io/<仓库名>/`

单测不过就不部署——还原链路一旦坏了，发上去的版本会静默产出错误终稿。`vite.config.ts` 里 `base: './'` 用相对路径，部署在 `/<repo>/` 子路径下无需改配置。

## 项目结构

```
src/
  core/                 纯函数，零 DOM 依赖，可单测
    checksum.ts         身份证 / 信用代码 / 银行卡校验位
    numeric.ts          数值识别（分级放行，控制误伤）
    rules.ts            标识符识别（含股票代码、域名、地址）
    lexicon.ts          从正文抽取候选主体（机构 / 简称 / 人名 / 项目）
    dict.ts             Aho-Corasick 词表匹配
    alias.ts            简称抽取与别名扩展
    overlap.ts          重叠裁剪
    detect.ts           检测流水线
    ledger.ts           实体归并、占位符分配、按行对齐切分
    restore.ts          容错还原与三类诊断
    prompt.ts           送给外部 AI 的提示词模板
  components/           五步界面 + 使用说明弹层
    ImportStep.tsx      导入材料、主体清单
    MaskStep.tsx        双栏对比、类型下钻、手动标记与撤销
    ExportStep.tsx      脱敏稿与提示词导出
    PasteStep.tsx       粘回润色稿
    ResultStep.tsx      还原结果与诊断
    HelpDialog.tsx      标题右侧的「使用说明」
  io/files.ts           文件解析（mammoth 懒加载）
  export/text.ts        复制与下载
  store.ts              会话状态（zustand）
  types.ts              实体类型与账本结构
tests/                  67 个单测：校验位、数值分级、词表、往返一致性、破坏性改写…
```

数据流：`原文 → 候选命中 → 实体账本 → 占位符 → 脱敏稿 →（外部 AI）→ 粘回 → 按账本还原`

## 技术栈

Vite + React + TypeScript，状态用 `zustand`，DOCX 用 `mammoth` 解析，导出为 Blob 下载。核心逻辑全部是纯函数放在 `src/core/`，与界面完全解耦，所以能直接跑单测、也能整段搬到别的宿主里。

## 已知边界

- **不支持扫描件 PDF**（没有文本层，需先 OCR）、**不支持 `.doc` 旧格式**（请另存为 `.docx`）、**不支持 Excel / PPT**。
- **不保留原文档样式**：导出是纯文本，段落层级在，字体与表格样式不在。
- **金额单位会一起进占位符**（`1.85 亿元` → `〔金额_1〕`），所以 AI 看不到量级。这是拿「还原逐字一致」换来的：AI 只能做语言润色，做不了数值推理。
- **没有 NER 模型**：人名、公司简称靠候选抽取 + 别名扩展，默认全选后建议扫一眼清单。
- **不做勾稽校验**：数值全部走占位符，脱敏稿里本来就没有数字可校验。
- **单文件处理**：一次一份材料，不做批量。
