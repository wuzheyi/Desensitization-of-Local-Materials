# 尽调材料脱敏 · 可逆还原

把金融尽调材料里的主体信息与金额比例替换成占位符，交给外部 AI 润色后，再在本地把占位符还原成原始信息。

**原始文本、实体账本、还原结果全部留在浏览器内存里，不上传、不落盘、不发任何网络请求。**

## 它解决什么问题

尽调材料不能直接丢给 AI——里面全是交易对价、客户名单、股权结构和自然人信息。但只做常规脱敏又有个副作用：脱完就还原不回来了，AI 改过的稿子没法再对回原文。

这个工具的做法是「可逆脱敏」：

```
原文 ─脱敏─▶ 脱敏稿（含 〔机构_1〕〔金额_2〕 等占位符）
                    │
                    ├─ 导出 / 复制 ─▶ 你自己的 AI 润色
                    │
             粘回润色稿 ─▶ 按本地账本反向还原 ─▶ 终稿
```

工具本身不调用任何模型，也就没有把柄可抓：它只负责「生成本地可控的脱敏稿」和「把 AI 的成果变成能用的终稿」这两件事。

## 主流程（五步）

1. **导入** — 拖入 `.docx` / `.txt` / `.md`，或直接粘贴。文件在浏览器里解析，不上传。
2. **识别与对比** — 左原文右脱敏稿，按行对齐逐行比对。
   - **双向联动**：点原文任一命中处，右侧对应占位符同步高亮；点占位符，左侧原文同步高亮。同一主体在全文出现几处，就一起亮几处。
   - **统计可下钻**：顶部「机构 6 / 金额 5」这些标签可点击，展开看这一类具体命中了哪些词、各出现几次、来自规则还是词表，点某一条即定位到正文。
   - **全文同步脱敏**：选中一段文字，确认前就会告诉你「全文 N 处相同内容会一起脱敏」；标记后这些位置同时脉冲提示。撤销同理，撤销过的位置用红色虚线框加删除线标出，可一键恢复。
3. **导出脱敏稿** — 一键复制（可附带提示词），或下载 `.txt`。
4. **粘回润色稿** — 把 AI 返回的全文粘回来。
5. **还原与导出** — 逐条列出还原情况：哪些占位符缺失（AI 删了）、哪些是 AI 自造的、正文里是否还有残留，然后导出终稿。

## 识别什么

**主体与关联标识**（能反查到具体公司的都算）：身份证、统一社会信用代码、手机/座机、邮箱、银行卡、地址、车牌、IP、股票代码（含 `.SH/.SZ/.HK` 后缀与「代码：」上下文）、域名、完整 URL。

**金额与财务**：金额（含中文大写、括号负数、万元/亿元换算）、比例、数量。

**为什么不误伤**：4 位数字可能是年份、条款号、编号，一律放过；无单位的裸数字只有带千分位或小数点且 ≥ 1000 才脱敏；`3 家子公司` 这类小数量保留，否则文本会被切碎到不可读。年份默认保留，日期脱敏是可选项。

**主体名称**是唯一无法靠正则兜住的部分，所以做了一层自动抽取：点一下「从正文抽取候选实体」，工具会用四类线索扫全文，列出候选让你勾选，勾完一键并入词表。

| 线索 | 能抓到什么 |
|---|---|
| 机构后缀 | 以「有限公司 / 集团 / 银行 / 事务所 / 中心 / 协会」等结尾的全称，包括带括号的 `天健会计师事务所（特殊普通合伙）` |
| 「以下简称」句式 | `深圳市前海云启科技有限公司（以下简称"云启科技"）` 里的简称，自动绑定到同一主体 |
| 职务与称谓 | 「法定代表人：陈立平」「王振华先生」「由李明持有」这类上下文里的人名，含并列人名 |
| 项目名 | 「启元一号项目」，书名号里的非文件类名称 |

抽取结果是**候选**，默认只勾高置信项，需要你确认才进词表——因为启发式一定有误报，而误脱敏（把普通词替换成占位符）比漏脱更毁体验。

进词表之后还有一层自动扩展：去掉行政区域和行业后缀生成别名，同一主体的不同写法都会脱。

## 还原是怎么做到可靠的

AI 一定会改写占位符的形态。实测中它会把 `〔机构_1〕` 写成 `【机构1】`、`(机构 1)`、`[机构_1]` 甚至断行。所以还原不能用严格字符串替换：

- **括号种类宽松**：`〔〕 [] 【】 （） () ｛｝ 「」` 都认
- **分隔符可选**：`_`、`-`、空格、`.` 都行，没有也能匹配
- **序号归一**：`001` 与 `1` 等价
- **多占位符并列**：`〔机构_1、机构_2〕` 能被拆开分别还原
- **绝不静默输出**：缺失、未知、残留三类问题都会逐条报出来

文号里的 `〔2020〕` 因为不含「类型+序号」结构，不会被误当成占位符。

## 部署到 GitHub Pages

完整步骤见 **[docs/DEPLOY.md](docs/DEPLOY.md)**，包含需要上传哪些文件、两个硬门槛、自检清单和常见失败排查。简短版：

1. 仓库设为 **Public**，默认分支 **main**
2. 推到 `main`，Actions 自动构建（先跑单测，不过就不部署）
3. Settings → Pages → Source 选 **GitHub Actions**
4. 网址是 `https://<用户名>.github.io/<仓库名>/`

`vite.config.ts` 里 `base: './'` 用的是相对路径，所以部署在 `/<repo>/` 子路径下不用改配置。

## 已知边界

- **不支持扫描件 PDF**：没有文本层，需要先 OCR。`.doc` 旧格式请另存为 `.docx`。
- **不保留原文档样式**：导出是纯文本，段落层级在，字体表格样式不在。
- **金额的单位会一起进占位符**（`1.85 亿元` → `〔金额_1〕`），所以 AI 看不到量级。这是拿「还原逐字一致」换来的，代价是 AI 只能做语言润色，做不了数值推理。
- **没有 NER 模型**：人名、公司简称靠候选抽取 + 词表 + 别名扩展。抽取是启发式的，长材料建议扫一遍候选列表再开始。
- **不做勾稽校验**：所有数值走占位符，脱敏稿里本来就没有数字可校验。

## 技术栈

Vite + React + TypeScript，`mammoth` 解析 DOCX，`docx`/Blob 导出，核心逻辑是与 DOM 无关的纯函数（`src/core/`），可直接单测。

```
src/core/
  checksum.ts   身份证/信用代码/银行卡校验位
  numeric.ts    数值识别（分级放行，控制误伤）
  rules.ts      标识符识别
  lexicon.ts    从正文抽取候选实体（机构/简称/人名/项目）
  dict.ts       Aho-Corasick 词表匹配
  alias.ts      简称抽取与别名扩展
  overlap.ts    重叠裁剪
  detect.ts     检测流水线
  ledger.ts     实体账本、占位符分配、按行对齐
  restore.ts    容错还原与诊断
```
